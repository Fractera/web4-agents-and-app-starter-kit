# Свой домен: когда, чем и чего не делать

## 1. Два пути в интернет, и путать их дорого

| | Временный адрес | Свой домен |
|---|---|---|
| имя | `четыре-слова.trycloudflare.com`, выдаёт Cloudflare | принадлежит человеку |
| живёт | часы; меняется при каждом перезапуске | всегда |
| вход и регистрация | **выключены**: сессия привязана к имени | работают |
| поисковики | не индексируют | индексируют |
| поднимается | `npm run serve:publish` | лестницей на вкладке «Активация домена» |
| житель pm2 | `fractera-web4-tunnel` | `fractera-web4-domain` |

🔒 **Они живут рядом, а не вместо друг друга.** Пока домен не отвечает, человек не должен остаться
без сайта: запись DNS расходится минутами, и это время он не контролирует.

## 2. Чего НЕ делать никогда

🛑 **Не перезапускать быстрый туннель по своей инициативе.** Решение владельца 2026-09-19, дословно:
«Не трогать, только честно сообщать». Перезапуск даёт НОВЫЙ адрес — ссылка, которую человек уже
кому-то дал, умрёт молча. Отказ помечается в состоянии и называется вслух вместе с командой.

🛑 **Не подключать домен молча.** Выход в интернет — отдельное решение человека, а не побочный
эффект. Тем более чужой домен: это его имя, его деньги, его репутация.

🛑 **Не предлагать постоянный адрес от нас.** Владелец отверг это прямо: выдавая адреса, мы обязаны
жить вечно, и упавшая Fractera погасила бы все сайты разом. Временный адрес, который человек меняет
на собственный домен, этой проверке удовлетворяет; выданный нами — нет.

## 3. Когда идти в MCP Cloudflare

Сервер `cloudflare-api` объявлен в `.mcp.json` корня. Иди туда, когда **человек попросил разобраться**
и обычных дверей узла не хватает:

- зона у Cloudflare есть, но `активна ли` неизвестно — посмотреть статус;
- запись DNS создана, а имя не отвечает — сверить, что лежит в зоне на самом деле;
- туннель создан, но `cloudflared` пишет отказ — посмотреть туннель со стороны Cloudflare;
- человек хочет понять, каких прав не хватило его токену.

🔒 **Вход по OAuth: человек сам выбирает права в окне Cloudflare.** Ключей в `.mcp.json` нет.

🛑 **MCP — для разбора, а не для рантайма.** Всё, что должно работать без агента — создание туннеля,
запись DNS, запуск `cloudflared` — уже построено дверями узла (`/api/domain/*`). Переписывать это на
MCP запрещено: сайт перестал бы вставать без чужой живой службы и без человека у браузера.

## 4. Где что лежит

| Что | Где |
|---|---|
| лестница подключения | `components/domain/domain-ladder.client.tsx` |
| обращения к API | `lib/domain/cloudflare.ts` |
| двери | `app/api/domain/state`, `/key`, `/activate` |
| житель и его сторож | `scripts/domain-tunnel.mjs`, `ecosystem.config.cjs` |
| что вышло | `logs/domain.json`, `logs/domain-tunnel.json` |
| состояние вслух | `npm run serve:status` — строка «свой домен» |

## 5. Три шага вне дверей узла — и как с ними помочь

Купить домен · завести зону в Cloudflare · **сменить серверы имён у регистратора**. Дверями узла и MCP их не сделать: пока зона не
делегирована, власти над ней нет ни у нас, ни у MCP.
🔒 С шага 616 (владелец 2026-10-30: «Моя основная задача подключить домен») два из них главный агент делает в Chrome человека — навык
`help-in-browser`: завести зону в его Cloudflare и сменить серверы имён у его регистратора, после его «да», когда он у этого компьютера и
сам вошёл на сайт. Купить домен — оплата, её делает человек (агент может подготовить выбор). Человеку это говорится сразу, а не после
нескольких неудачных попыток.
